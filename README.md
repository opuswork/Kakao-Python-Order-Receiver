# 카카오 주문 수신 서버

FastAPI / Python 3.12. 카카오톡 채널 챗봇 스킬로 들어온 간장 주문을 관리자 화면의 **제품주문서(신규작성)**와
같은 형태로 만들어 기존 주문 API(`POST /api/orders`)에 접수합니다. 기본값 `DRY_RUN=true`에서는 대화와
미리보기까지만 하고 주문은 보내지 않습니다.

## 연결 흐름

카카오 채널(남부장유매장) → 챗봇 폴백 블록 → 스킬 `POST /kakao/order` → 대화로 주문서 채우기 →
미리보기와 [주문 확정] 버튼 → 확정 시 주문 API 1회 호출.

## 채팅 주문서

첫 메시지에 들어 있는 값은 그대로 쓰고, 빠진 값만 순서대로 묻습니다. 선택지는 버튼으로 보여 줍니다.

| 순서 | 항목 | 첫 메시지 예 | 없을 때 |
|---|---|---|---|
| 1 | 상품·수량 | `1급진간장 1.8L 10박스` (여러 줄 가능) | 질문. 상품 DB에서 이름+단위로 찾고 여러 개면 번호 선택 |
| 2 | 납품(발송)일 | `11월 10일`, `11/10`, `27일납품` | 질문 |
| 3 | 매장 | `남부`, `주문매장: 중부` | [남부][중부][서부] |
| 4 | 주문자 | `주문자: 홍길동 010-1234-5678`, `홍길동 010-1234-5678` | 저장된 주문자가 있으면 [네][다른 분 주문], 없으면 질문 |
| 5 | 중앙 | `중앙: 서대문남` | 기존 회원이면 회원의 중앙, 아니면 검색(예: 5, 서울) 후 선택 |
| 6 | 받는 곳(업체) | `청운초등학교` (분류되지 않은 항목) | 질문 |
| 7 | 받는분·주소 | `받는분: 함은숙 010-…`, `주소: …` | 거래처관리에서 업체 이름으로 찾아 확인, 없으면 한 줄 입력 |
| 8 | 배송 방법 | `택배`, `배달` | [택배][배달] |
| 9 | 배달 시간 (배달만) | `오전 10시`, `배달시간: 05:00` | 질문 |

- 항목은 쉼표, 줄바꿈 또는 ` / `로 나눕니다. 순서는 상관없고 "주문합니다", "(테스트)" 같은 끝말은 무시합니다.
- `취소`/`처음부터`는 입력 중인 주문을 버립니다. 날짜와 상품이 모두 있는 새 주문을 보내면 진행 중인 주문을 대체합니다.
- 입력 중인 주문은 30분 동안 유지됩니다(`kakao_receiver_sessions`).
- 처음 입력한 주문자는 그 카카오 사용자의 기본 주문자로 기억합니다(`kakao_receiver_profiles`).
  `주문자 변경`으로 지울 수 있습니다. 대리 주문은 [다른 분 주문]으로 하고 기본 주문자는 바뀌지 않습니다.
- 카카오는 보낸 사람의 이름·전화번호를 주지 않습니다. 주문자는 항상 입력받은 이름+전화번호로 정합니다.
- 선물세트(인사장 필요)는 받지 않습니다. 앱에서 주문하도록 안내합니다.

## 주문 API에 보내는 값

`be/`, `fe/` 코드(제품주문서 `OrderListInput.tsx`, `OrdersService`)를 기준으로 맞췄습니다.

- **주문 회원**
  - 회원 검색(`GET /api/members/search?q=이름`) 결과 중 전화번호가 같은 회원이 있으면 그 `userId`로 접수합니다.
  - 없으면 `userId`=관리자 + `ordererProfile {fullname, phone, churchId}`를 보냅니다.
    `OrdersService`가 전화번호로 기존 회원을 찾거나 새 회원을 만듭니다(이름은 비교하지 않음).
  - 관장·총무 회원은 앱과 같이 `주문자:` 이름 끝에 "관"을 붙입니다.
- **notes**: 앱과 같은 순서와 세그먼트를 씁니다.
  `주문자 / 연락처 / 주문일자 / 중앙 / (배달업체명·배달일·받는분 | 택배업체명·택배발송일·보내는사람·받는분성함) /
  수취연락:주소 / 받는분주소 / 주문작업지역 / 지부매장 / 인사장종류:없음 / [택배|배달] 상품 n개 / 배송상세:<base64url>`
  - 매장은 `남부(기장)`, `중부(덕소)`, `서부(소사)`로 적고, 백엔드가 `주문작업지역:`에서 storeRegion을 읽습니다.
  - 사용자 입력의 `/`와 줄바꿈은 공백으로 바꿉니다(notes 구분자 보호).
- **택배 보내는사람**: 주문자 이름·전화번호 + 받는분 주소(회원 주소 정보가 없어서). 기존 PC 자동화와 같은 대체 방식입니다.
- **shipment**: `PARCEL`, carrier=업체명. deliveryAddress는 배달이면 받는분 주소, 택배면 보내는사람 주소입니다.
  estimatedWindow는 택배 `날짜T09:00:00.000Z`, 배달 `날짜T배달시각:00.000Z`(앱과 같은 표기)입니다.
- **상품**: 상품 DB의 `productName`을 그대로 보냅니다(재고 차감이 이름 일치로 동작). 단가는 `wholesalePrice`이고 합계는 수량×단가입니다.
  입력 단위는 상품명 `(박스)`/`(개)` 표기와 같아야 하며 자동 환산은 없습니다.
- 한 주문서는 한 번의 POST(상품 여러 줄 포함)로 보냅니다. 모든 줄의 배송 정보가 같아서 줄별 분할이 필요 없습니다.
- `extraNote`에 `카카오접수:확인ID`를 넣어 응답이 유실돼도 주문앱 기록과 대조할 수 있게 합니다.

## 중복·재전송 방지

- 확정 전 초안은 15분간 유효합니다. 같은 사용자·주문자 전화·날짜·업체·배송방법·상품·수량은 같은 주문으로 봅니다.
- PostgreSQL 조건부 UPDATE로 확정을 한 번만 처리하고, 주문 POST는 자동 재시도하지 않습니다.
- 타임아웃이나 확인되지 않은 응답은 `unknown`으로 남기고 재전송하지 않습니다. 주문앱에서 `카카오접수:` 메모로 대조하세요.
- 응답의 `userId`는 기존 회원이면 보낸 값과 같아야 하고, 신규 주문자면 양수 회원 ID여야 성공으로 봅니다.

## 배포와 설정

환경변수는 `.env.example` 참고. 이 저장소는 공개 저장소이므로 실제 값은 Vercel 환경변수에만 넣습니다.

1. 수신 DB에서 `schema.sql`을 실행합니다(세션·기본 주문자 테이블이 추가됨). 자동 마이그레이션은 없습니다.
2. Vercel 환경변수: `KAKAO_SKILL_SECRET`, `SANC_API_BASE_URL=https://be-aosm.onrender.com`,
   `SANC_API_TOKEN`(관리자 JWT), `RECEIVER_DATABASE_URL`, `DRY_RUN`.
   - `DRY_RUN=true`여도 상품·회원·중앙·거래처 조회에는 관리자 토큰이 필요합니다.
   - `DRY_RUN=true`이고 DB 주소가 없으면 메모리에 대화를 저장합니다. 서버리스 인스턴스가 바뀌면 대화가 끊길 수 있어 테스트용입니다.
   - `DRY_RUN=false`에는 DB가 필수입니다.
3. 카카오 스킬 URL `https://<배포주소>/kakao/order`, 헤더 `X-Kakao-Skill-Key`=`KAKAO_SKILL_SECRET`.
   폴백 블록에서 스킬 데이터를 사용합니다.
4. 채널에서 `연결확인`으로 연결을 확인합니다.
5. main 브랜치가 Vercel Production, dev 브랜치는 Preview로 배포됩니다.

서버 처리 제한은 3.5초입니다(카카오 응답 제한 5초). 조회가 필요한 단계에서만 백엔드에 연결합니다.
Render 백엔드가 잠들어 있으면 첫 응답이 늦어 시간 초과가 날 수 있습니다.

## 로컬 실행과 검증

```bash
pip install -r requirements-dev.txt
uvicorn main:app --reload
python -m pytest -q
```

테스트는 백엔드와 DB를 대체해 실제 주문을 만들지 않습니다. 실제 PostgreSQL 동시성과 운영 백엔드 연동은 배포 후 확인합니다.
